判定指纹：结论的边界

同一个路径在不同时间可能是不同对象；指纹是缓存复用与删除守卫的共同键。

key+size+mtime+is_dir →fingerprint
分析时写入 verdict：这是一个 4GB 缓存，不是一个路径。
复用时四项完全匹配才命中；任一变化即重判。
删除前重新 stat；不匹配就拒绝，哪怕用户刚点过确认。
清理后结论离开 cleanable；历史与决策仍然保留。

05

不变量与已知缺口

左边是必须永远成立的规则；右边是当前实现仍需要补齐的一致性点。

安全规则优先于
性能与便利

不变量

  • 01
    只有 Safe 进入 cleanable；Review 是问题，不是长期许可。
  • 02
    删除前重验指纹；last_report + stat + 置信度，缺一不可。
  • 03
    epoch 单调；旧扫描的迟到批次不能重建新树。
  • 04
    精确值不被 derived 覆盖；父目录的直接文件不能被丢掉。
  • 05
    前后端各扣一次；目录子树与文件不重复扣。
  • 06
    模型不能单独授权删除；sanitize 是唯一入口。

仍待闭环

  • 01
    外部删除只剪前端树，不同步 size-tree / listing。
  • 02
    清理后 ScanTree 仍是旧快照；立即分析可能看到已删路径。
  • 03
    size-tree.json 无 schema 版本，非原子写；超过 64 MB 会移到 .oversized 后重建。
  • 04
    空目录不进尺寸树；peek 返回 partial，触发走盘。
  • 05
    listing 5m / size 30m 的 TTL 不一致，外部变化时可能不同步。
  • 06
    前端尺寸缓存不持久；冷启动依赖后端索引。
